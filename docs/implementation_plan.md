## Этапы

### Этап 1. Документация и безопасный каркас (текущий)

Результат: обязательные документы, нормализованные входы, operator inputs/evidence, структура репозитория и fail-closed управляющие скрипты.

Изменяемые файлы: только документация, placeholders, каркас, Makefile и `scripts/*`.

Проверка:

```bash
make validate
make bootstrap
make up
make smoke
```

`validate` должен проверить статический каркас. Остальные команды обязаны завершаться ошибкой, пока отсутствуют prerequisites или будущие компоненты.

Готовность: все артефакты этапа существуют; оригиналы входных markdown сохранены; секретов нет; production-сервисы не запущены.

Откат: удалить только добавленные в этом этапе файлы и пустые каталоги. Исходные файлы с `(1)` не затрагивать.

### Этап 2. Контракты и локальная инфраструктура

Зависимости: одобрение этапа 1, Docker/Compose и согласованные версии. Результат: схемы API/очереди/manifest, compose-профиль и external DB stub. Проверка: schema tests и локальные healthchecks. Откат: остановка compose и удаление только временных локальных volumes после отдельного подтверждения.

### Этап 3. Upload, хранение и оркестрация

Зависимости: доступное тестовое S3 с versioning/retention. Результат: multipart upload, probe, очередь, idempotency и result-writer. Проверка: прерванная загрузка, повторная доставка, checksum и запрет перезаписи. Откат: отключение consumers без удаления originals.

### Этап 4. GPU-конвейер

Зависимости: approved-модели с SHA-256, обе ноды и тестовые видео. Результат: потоковая обработка одного видео одним worker, manifest и compressed derivative. Проверка: benchmark, recovery и две параллельные задачи. Откат: возврат на предыдущий versioned model/pipeline manifest.

### Этап 5. Web/mobile и пилот

Зависимости: стабильные API и OIDC. Результат: карта, GPS/accuracy/direction, заметки, resumable upload, статусы и отчёты. Проверка: сценарии из `acceptance_tests.md`. Откат: развернуть предыдущие неизменяемые образы.

## Основные риски

- RTX 3090 и 31 GiB RAM могут ограничить одновременный inference и инфраструктурные сервисы;
- совместимость DeepStream 9.1, драйвера 570 и выбранного TensorRT требует проверки;
- отсутствие S3 блокирует корректную реализацию multipart и immutable originals;
- отсутствие taxonomy/датасета блокирует обучение классификатора;
- отсутствие worker-ноды блокирует проверку распределения и восстановления;
- web URL внешней системы нельзя трактовать как DSN.

## Действия оператора

1. Проверить документы этапа 1.
2. Предоставить evidence второй ноды.
3. Установить Docker и NVIDIA Container Toolkit вне этого этапа, затем передать вывод проверок.
4. Предоставить S3 endpoint/region и свойства versioning, Object Lock/retention и backup без секретов в Git.
5. Предоставить approved-модели и SHA-256.
6. Согласовать `vehicle_size_taxonomy.md`, спорные случаи и закрытый тестовый набор.
7. Предоставить тестовое видео и ожидаемый отчёт.
8. Для внешней БД передать только утверждённые параметры и путь к secret-файлу; до этого оставить stub.
